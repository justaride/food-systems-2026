# Food TG Decision Pack v0.1

## 0. Status

**Formål:** Gi JTO/Cathrine/Einar et kontrollert beslutningsgrunnlag for om Food TG skal få minimumsvedtak til å starte en begrenset valideringssprint.

**Status:** Intern beslutningspakke. Dette er ikke ekstern presentasjon, ikke whitepaper, ikke pilotløfte og ikke validert roadmap.

**Viktig avgrensning:** Ingen claims løftes til eksternt validert gjennom denne pakken. Scope er fortsatt ikke formelt bekreftet per 2026-05-21.

## 1. Beslutningen vi ber om nå

Det anbefales å be om minst dette minimumsvedtaket:

```text
Food TG kan kjøre en begrenset valideringssprint på A+B/C-hypotesen uten at dette regnes som endelig scope- eller pilotcommitment.
```

Hvis gruppen er klar til full scope-beslutning, anbefales dette:

```text
Food TG går videre med Spor A+B som hovedscope, med Spor C som tverrgående adoption-, regelverks- og datagate. Gruppen kjører en 10 arbeidsdagers valideringssprint før pilotcommitment. Ingen claims løftes til ekstern validert status før primærsjekk eller aktørvalidering er dokumentert.
```

## 2. Kort executive summary

Food TG har nå nok intern substans til å gå videre metodisk, men ikke nok ekstern forankring til å skrive pilot, finansiering eller roadmap i faktastemme.

Kunnskapsbasen er sterk på:

- fôr/import/EUDR som strategisk datalag
- alternative fôrproteiner som roadmap-spor
- prosess-sidestrømmer som teknisk kandidatfelt
- matsvinnkvalitet som mulig lavterskel adoption-case
- C-gate: lov, kjøper, data, drift, governance og KPI-minimum

Det som mangler er ikke først og fremst mer bred research. Det som mangler er:

- formelt scope- eller minimumsvedtak
- aktørvalidering
- bruksrett til eventuelle aktørsvar
- casevise data for råvare, hygiene, kjøper, baseline og systemgrenser
- kilde-/locator-lock på high-risk claims før ekstern tekst

## 6. Spor A: fôr, import og sporbarhet

**Beslutningsjobb:** Avklare om Spor A skal være roadmap-spor, datagate og mulig senere pilotfelt.

**Trygg formulering nå:**

> Alternative fôrproteiner er relevante roadmap-spor for importsubstitusjon dersom modenhet, kost, LCA, råvaretilgang, regulatorisk vei og kjøperkrav bekreftes.

**Datalag som ikke må blandes:**

| Datalag | Bruk | Ikke bruk som |
|---|---|---|
| SSB/HS 08801 | Importserie per varenummer. | Faktisk fôrbruk eller SPC-serie uten metode. |
| Fiskeridirektoratet/Sjømat Norge | Total oppdrettsfôr-volumramme. | Råvareandel eller substitusjonseffekt. |
| Denofa/Skretting/BioMar | Actor-/benchmarkdata. | Norsk bransjesnitt. |
| EUDR EU-scope | Sporbarhets- og compliance-driver. | Norsk soya-plikt uten norsk/EØS-status. |
| NMBU/Foods of Norway | FoU- og teknisk relevans. | Kommersiell modenhet eller pilotvolum. |

**Må valideres:**

- EUDR EU/Norge/EØS-scope
- SPC/metode og varekodeforståelse
- aktørdata og bruksrett
- modenhet, kost, LCA og kjøperkrav
- regulatorisk vei

## 7. Spor B1: okara/BSG som teknisk kandidat

**Beslutningsjobb:** Avklare om ren prosess-sidestrøm kan bli konkret pilotkandidat, eller skal holdes som benchmark.

**Trygg formulering nå:**

> Okara og bryggerimask er konkrete benchmark og betingede kandidatstrømmer, men norsk/nordisk volum, food-grade, holdbarhet og off-taker må valideres.

**Minimumsdata før pilotord brukes:**

| Felt | Må avklares |
|---|---|
| Råvareeier | Hvem eier strømmen og kan dele data? |
| Volum | Tonn/år og batchfrekvens. |
| Kvalitet | Fukt/tørrstoff, temperatur, mikrobiologi og variasjon. |
| Nåværende avsetning | Mat, fôr, biogass, avfall eller annet. |
| Stabilisering | Kjøling, tørking, fermentering eller annen prosess. |
| Lovlig sluttbruk | Mat, ingrediens, fôr eller annet. |
| Off-taker | Hvem kan kjøpe eller bruke output? |
| Bruksrett | Kan data siteres, eller bare brukes internt? |

## 8. Spor B2: matsvinnkvalitet som adoption-kandidat

**Beslutningsjobb:** Teste om matsvinnkvalitet kan bli raskere adoption-case enn en tung fysisk prosesspilot.

**Trygg formulering nå:**

> Matsvinnkvalitet kan være en rask adoption-kandidat hvis partner dokumenterer baseline, kategori, tidsvindu, destinasjon og rutineendring.

**Minimumsdata før effektord brukes:**

| Felt | Må avklares |
|---|---|
| Partner | Matvett, TGTG, butikk, HORECA eller offentlig kjøkken. |
| Kategori | Hvilke varer/fraksjoner. |
| Tidsvindu | Når kvalitetstap skjer. |
| Baseline | Nåværende volum, destinasjon og rutine. |
| Tiltak | Hva endres i drift. |
| Kontrafaktisk | Hva ville skjedd uten tiltak. |
| Dataeier | Hvem kan dokumentere og dele. |
| Bruksrett | Hva kan siteres. |

## 9. Benchmark som skal beholdes, men ikke selges som pilot

| Benchmark | Behold som | Ikke bruk som |
|---|---|---|
| Marint restråstoff | Fraksjons- og høyverdi-læring. | Første B-pilot. |
| RecoLab/Helsingborg | Governance, N/P/K og produktstatus. | Kopierbar norsk pilot. |
| VEAS/HIAS/Den Magiske Fabrikken | Infrastruktur- og nutrient-loop læring. | Lettvekts-pilot eller sammenlignbar KPI uten systemgrense. |
| Salling Group | Retail-/matsvinn benchmark. | Nordisk rangering eller norsk effekt. |
| Danmark Green Tripartite | Policy-benchmark. | Norsk overførbarhet uten separat analyse. |

## 10. C-gate for alle kandidater

C er ikke et bredt separat policyspor nå. C er gate for A og B.

| Gate | Spørsmål | Stoppsignal |
|---|---|---|
| Lov | Er bruken lovlig nå? | Bare regulatorisk mulighet, ingen lovlig vei. |
| Kjøper | Hvem kjøper eller bruker output? | Ingen off-taker. |
| Data | Hvem eier baseline og løpende data? | Ingen dataeier. |
| Drift | Hvem må endre rutine/logistikk/prosess? | Ingen operativ eier. |
| Governance | Hvem kan beslutte og bære risiko? | Ingen styringsarena. |
| KPI | Hva kan måles med definisjon og frekvens? | KPI uten baseline/systemgrense. |

## 13. Go/no-go etter sprint

| Funn | Handling | Språk etterpå |
|---|---|---|
| Gate åpner med data og aktør | Skriv pilotbrief. | `pilotkandidat`, ikke `pilotklar`. |
| Gate åpner delvis | Hold som scoping/roadmap. | `klar-med-forbehold`. |
| Bare læring, ingen eier | Flytt til benchmark. | `benchmark`. |
| Regelverk/data blokkerer | Parker eller watchlist. | `hold-tilbake` eller `parkert`. |
| Funn motsier nåværende claim | Harmoniser claim og kilde. | `maa-harmoniseres`. |
