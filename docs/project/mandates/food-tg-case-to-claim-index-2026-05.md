# Food TG Case/Pilot-to-Claim Index 2026-05

**Status:** Intern kontrollindeks
**Dato:** 2026-05-21
**Scope-status:** Kan fylles som hypotese uten scope-vedtak. Outreach og statusløft krever scope- eller minimumsvedtak.
**Bruksregel:** Et case kan være nyttig uten å være pilot. Denne indeksen skal hindre at benchmark, hypotese, pilotkandidat og effektbevis blandes.

## Statusnøkkel

| Status | Betydning |
|---|---|
| `benchmark` | Kan brukes til læring, designkrav eller sammenligning. Beviser ikke norsk pilotbarhet. |
| `hypotese` | Gir arbeidsspor eller spørsmål. Må ikke skrives som konklusjon. |
| `pilotkandidat` | Kan modnes mot pilot hvis eier, data, lov, kjøper, drift og finansiering avklares. |
| `sekundaerspor` | Relevant, men for tungt, smalt eller uavklart som første pilot. |
| `hold-tilbake` | Skal ikke brukes i ekstern tekst slik det står. |

## Kandidatkort som bør bygges videre

| Kandidatkort | Første spørsmål | Minimumsdata før pilotord brukes | Stoppsignal |
|---|---|---|---|
| A1: Alternative fôrproteiner | Er dette roadmap-spor, FoU-benchmark eller senere pilot? | Modenhet, kost, LCA, råvaregrunnlag, regulatorisk vei, kjøperkrav, aktørdata. | Fôraktører kan ikke validere modenhet eller data. |
| A/B: Insektprotein på godkjente sidestrømmer | Finnes lovlig, ren og trygg substratstrøm med kjøper? | Substratliste, TSE/ABP, risiko, aktørkapasitet, fôr-/sjømatkjøper. | Substrat er ikke lovlig eller ikke dokumenterbart. |
| B1: Okara/BSG | Finnes råvareeier, holdbarhet og off-taker? | Tonn/år, batch, fukt, temperatur, mikrobiologi, nåværende avsetning, logistikk, sluttbruk. | Råvareeier eller fagekspert kan ikke åpne gate. |
| B2: Matsvinnkvalitet | Kan partner vise kvalitetstap før varen faller ned i kaskaden? | Baseline, kategori, tidsvindu, rutineendring, destinasjon, kontrafaktisk, dataeier. | Bare kommunikasjonsdata eller måltider reddet uten kontrafaktisk. |
| B3: Nutrient-loop benchmark | Hva kan Food lære uten å gjøre dette til første pilot? | Produktstatus, N/P/K, regelverk, systemgrense, marked og aktør. | Tung infrastruktur gjør pilot urealistisk i 2026-2027. |
| C-gate: Adoption og marked | Hvem må kjøpe, dele data, eie drift og tåle risiko? | Kjøper, dataeier, kontrakt, rapporteringsvern, governance, KPI-minimum. | Ingen tydelig styringsarena eller dataeier. |

## Språkregler

- Skriv `benchmark` når caset gir læring, men ikke pilotbevis.
- Skriv `kandidat` bare når det finnes en konkret gate og mulig eier.
- Skriv `pilotkandidat` først når minimumsdata er identifisert, men ikke bekreftet.
- Skriv aldri `pilotklar` før eier, data, lovlig sluttbruk, kjøper, drift og finansiering er dokumentert.
- Skriv aldri `effekt` uten baseline, kontrafaktisk og systemgrense.
- Skriv aldri `validert` uten dato, rolle, aktør, kilde og bruksrett.

## Neste handling

1. Bruk denne indeksen når `food-tg-validation-sprint-log-2026-05.md` åpnes etter minimumsvedtak.
2. Opprett ett kandidatkort per A1, A/B, B1 og B2 før outreach sendes.
3. Etter aktørrespons: oppdater status til `benchmark`, `pilotkandidat`, `sekundaerspor` eller `parkert`.
