# Lokal worktree-inventar etter PR-backlogg-closeout

## Kort konklusjon

GitHub PR-flaten var tom og `main` var rent mot `origin/main` før master-research-porteringen startet. MCP-sporet er publisert i PR #274 og den gamle lokale MCP-worktreen er fjernet. NotebookLM eksportsporet er publisert i PR #276 som fersk `2026-07-04`-pakke, og den gamle lokale NotebookLM-worktreen er nå fjernet etter eksplisitt port/drop-beslutning for recovery-restene. `ai-kunnskap` core/cockpit-slicen fra den gamle dirty worktree-en er publisert i PR #283, merget på `main`, og den ferske port-worktree-en er fjernet igjen. De read-only `library-analysis` inventory/ledger-, repair-backlog-, locator-profile-, PDF extraction- og URL text profile-generatorene er skilt ut som egne trygge port-slices. Prosess-projeksjonen er også skilt ut med eksplisitt dry-run/apply og stale-backup før prune, uten generated `research/_status` output. Library-triage kildestatusnotater er portet som content-only slice i PR #298. Etter PR #300 ble den gamle `codex/ai-kunnskap-library-v1`-worktreen bevist ferdig portet: 106 filer matchet dagens `main`, 66 gamle generated `_status`/triage-artefakter ble arkivert utenfor repo, og de få reelle code-differ var stale kopier som ikke skulle portes tilbake. Worktree og lokal branch er derfor fjernet. Første smale `codex/master-research-plan-2026-07-01`-slice ble tatt ut som remediation-review-port: HTML sidecar-tekst, low-text PDF-review og URL `other`-review kan lukke falske backlogg-rader uten å importere master-planens store forskningspakke. Andre smale master-research-slice tar MVK domain-registration metadata, slik at enrichment av eksisterende/global aktør ikke telles på feil land eller mister eldre domain/subdomain-registreringer. Tredje smale master-research-slice tar 2025 financial source locators for seks nordiske konsern uten å importere financial CSV-er eller større master-plan-output. Fjerde smale master-research-slice tar CA-005 fra intern juridisk blokkering til ekstern sitatklar sammenligning med Finlex- og KKV-locatorer. Femte smale master-research-slice lar `import-research-docs` hoppe over en byte-identisk duplicate PDF-alias i stedet for å importere den som separat supplemental-kilde. Sjette smale master-research-slice legger tester på remediation-backlogg og HTML text-sidecar-triage som allerede er portet. Restvurderingen etter sjette slice viser at gjenstående master-research-arbeid nå er dominert av DB-/filePath-/generated materialisering, ikke enkle code-differ: den slettede Salling/Coop-PDF-en er en byte-identisk fil, men `salling-coop-danmark-2025` er fortsatt et eget seedet report-id og `Document.filePath` er unik; de gamle backfill-/export-scriptflakene skriver database eller filer og noen har default apply. Disse skal derfor ikke blindportes uten eksplisitt dry-run/apply-kontrakt. Syvende smale master-research-slice tar bare den read-only nordiske board/ownership-auditen, med import-guard og testbar ren build-funksjon, uten generated `_status` output. Åttende smale master-research-slice tar 2025 Nordic financial import som DB-skriver, men endrer den til dry-run som default og separat `--apply` før `CompanyFinancial.upsert`. Niende smale master-research-slice tar country-metric harmonization på samme måte: dry-run default, separat `--apply`, testbare metodelabel- og marginbyggere, og ingen DB-skriving ved import. Tiende smale master-research-slice tar `Document.filePath`-backfill fra seed-map, kuratert lokalmap og direct-PDF download queue, men gjør også den til dry-run som default med `--apply`, path-eierskapskollisjon og import-guard. De tre rene ikke-ancestor worktreene, de to branch-only sporene, den gamle G-stacken og de opprinnelige dirty worktreene er også gjennomgått; de gjenværende sporene er beholdt fordi de enten har `+`-commits i `git cherry`, store stale tree-differ, eller uncommitted arbeid som ikke finnes i commits. Lokal repo-hygiene er derfor fortsatt ikke helt lik "slett alt": noen worktrees er dirty og skal ikke røres uten egen scopebeslutning, og noen rene worktrees/branches er beholdt som aktive eller mulige recovery-spor.

Ellevte smale master-research-slice tar missing-file snapshot-exporten, men bare som guarded materialisering fra eksisterende `Document.content`: dry-run er default, `--apply` kreves for markdown-filer og `Document.filePath` updates, og output merkes eksplisitt som locator/coverage-remediering, ikke fersk kildeverifisering.

Sluttklassifiseringen etter denne porteringen viser at det ikke finnes flere `scripts/*.ts` eller `tests/**/*.ts` som bare eksisterer i den gamle master-research-worktree-en. Det som fortsatt er dirty der, er hovedsakelig R13 research, MVK/generated statusmateriale, coverage/data-output, source notes og den kjente duplicate Salling/Coop-PDF-slettingen. Det skal derfor behandles som research/generated payload eller eksplisitt drop-beslutning, ikke som "mangler bare et script til".

Oppdatert etter PR #314 og PR #315: MVK import-payloaden, 86 manglende `db:import:mvk-*` scripts, `db:prod-sync` wiring, MVK guard-test og alle master-research old-only research/evidence/status-artefakter er landet på `main`. Etter den smale R13 controlled enrichment-porten viste korrigert innholdssammenligning mot den gamle worktree-en 381 filer som matchet `main`, 0 old-only filer, 29 filer som bare avvek fordi whitespace ble normalisert under import, 46 reelle existing-file differ og 2 deletion-/drop-beslutninger. Evidence/regulatory refresh-porten tar tre av disse diffene: funding-notat, roadmap-siterbarhetsfilter og nordisk enforcement-ledger. Aktiv rest er derfor 43 reelle existing-file differ og 2 deletion-/drop-beslutninger, ikke MVK, old-only source notes eller R13-filene som allerede var lengre/kontrollerte i master-research.

Dette notatet er en stoppregel for senere opprydding: slett bare en worktree/branch når den enten er ren og fullt innlemmet i `main`, eller når en eksplisitt beslutning sier at historikken ikke lenger skal beholdes.
