Vi har laget en trygg måte for Codex og Claude å lese prosjektets kunnskapsbase på. Poenget er enkelt: kollegaen kan stille vanlige spørsmål og få svar som viser hvor informasjonen kommer fra.

01 · Hva er dette?

Tenk på MCP som en kontrollert dør inn til kunnskapsbasen

AI-en får ikke rote fritt rundt. Den får en liten, ryddig meny: søk, hent et dokument, sjekk en påstand, vis kilden, eller finn hull i materialet.

For kollegaen

Still spørsmål på vanlig språk: “Hva vet vi om eierskap i nordisk dagligvare?”

For AI-en

Den får lov til å slå opp i riktig kunnskapsgrunnlag og returnere korte, kontrollerte svar.

For prosjektet

Svarene skiller mellom det vi kan sitere, det som bare er internt, og det som mangler kilde.

02 · Slik fungerer det i praksis

Fra spørsmål til svar med kilde og forbehold

1

Spør

Kollegaen stiller et vanlig spørsmål i Codex eller Claude.

2

Finn

Assistenten søker i dokumenter, selskaper, personer, aktører og kilder.

3

Sjekk

Den ser om funnet har kilde, lenke, lokal fil eller trenger gjennomgang.

4

Svar

Den gir kort svar med sitatstatus, ikke en stor datadump.

5

Varsle

Hvis noe er usikkert, sier den fra i stedet for å late som.

03 · Hva kan den hjelpe med?

Den gjør kunnskapsbasen mer samtalebar

Finne informasjon

Søk etter tema, dokumenter, selskaper, aktører eller personer uten å vite hvor i prosjektet dataene ligger.

Forklare sammenhenger

Be om korte profiler: hvem eier hva, hvilke dokumenter støtter dette, og hva er relasjonen?

Sjekke påstander

Gi den en konkret påstand og be den vise om prosjektet har kildebelegg for den.

Finne hull

List opp hva som mangler kilde, har lav tillit, eller bør ryddes før ekstern bruk.

Hovedregelen: Når noe ikke er godt nok dokumentert, skal assistenten si “dette er ikke klart for ekstern bruk” i stedet for å pynte på svaret.

04 · Hva vi bygget

En lesetilgang med rekkverk

Serveren kan bare lese. Den kan ikke endre databasen, importere filer, synke vaulten eller kjøre frie databasekommandoer. Det gjør den trygg nok som standardverktøy for kollegaer.

Søk

Finner relevante poster på tvers av kunnskapsbasen.

Hent

Viser korte dokumentutdrag og profiler med lenker.

Kontroller

Viser kildestatus, kildehull og usikkerhet.

05 · Hva kollegaen trenger å vite

Tre enkle ting holder

1. Spør konkret

“Hva vet vi om X?” er bra. “Kan dette siteres eksternt?” er enda bedre.

2. Be om kilder

Legg til “vis kildene og si hva som er usikkert”.

3. Ikke overtolk

Hvis assistenten sier at noe er internt eller usikkert, må det ryddes før ekstern bruk.

06 · Koble til Codex og Claude

Samme kunnskapsdør, ulike måter å åpne den på

For brukeren bør dette oppleves likt: åpne AI-verktøyet, se at Food Systems-kilden er koblet på, og spør med krav om kilder.

Der du jobber Hva betyr det i praksis? Anbefaling nå
Codex Codex starter kunnskapskoblingen fra repoet på maskinen din. Best førstetest. Dette er v1-hovedsporet.
Claude Code Claude kan kobles på fra terminalen på omtrent samme måte. Godt alternativ for tekniske kollegaer.
Claude Desktop Bør pakkes som en liten installasjonspakke før bred deling. Neste praktiske forbedring hvis desktop er viktig.
Claude web / Cowork Trenger en hosted versjon som kan nås utenfra. Ikke v1. Planlegg som v2 med innlogging og drift.

Enkel huskeregel: Codex og Claude Code kan bruke lokal kopi nå. Claude web/Cowork trenger en delt nettadresse senere.

07 · Eksempelspørsmål

Slik kan kollegaen spørre

Få oversikt

“Hva vet vi om matsvinn i kunnskapsbasen? Bruk bare funn som har gode kilder.”

Sjekk en påstand

“Kan påstanden om REMA 1000-eierskap dokumenteres? Vis kilde og usikkerhet.”

Forbered publisering

“Hvilke funn om nordisk dagligvare er klare for ekstern bruk, og hva må holdes tilbake?”

Finn ryddearbeid

“List de viktigste kildehullene for selskaper og aktører.”

08 · Praktisk oppsett

For brukeren: tre steg. For installatør: detaljer under.

Brukerens opplevelse

1. Få tilgang til repo og database. 2. Koble Food Systems-kilden til AI-verktøyet. 3. Start med et statusspørsmål.

Installatørens ansvar

Sørg for at tilgangen er lesetilgang, at hemmeligheter ikke ligger i repoet, og at Codex/Claude viser serveren som aktiv.

Teknisk detalj: Codex-kommando 
codex mcp add foodsystems-kb \
  --env DATABASE_URL="$DATABASE_URL" \
  --env OPENAI_API_KEY="$OPENAI_API_KEY" \
  -- npx tsx mcp/foodsystems-kb/server.ts

codex mcp list
# Restart Codex og åpne /mcp for å sjekke status.
Teknisk detalj: Claude Code-kommando 
claude mcp add --transport stdio foodsystems-kb \
  --env DATABASE_URL="$DATABASE_URL" \
  --env OPENAI_API_KEY="$OPENAI_API_KEY" \
  -- npx tsx mcp/foodsystems-kb/server.ts

claude mcp list
# Start Claude Code i repoet og bruk /mcp for status.

Claude Desktop bør pakkes som Desktop Extension før bred deling. Claude web/Cowork bør vente på en hosted versjon.

09 · Hva skjer nå?

Vi tester med ekte spørsmål før vi gjør den bredere

1. Koble til i Codex

Bruk ekte database-tilgang og sjekk at Food Systems-kilden er synlig.

2. Test 5-10 spørsmål

Velg spørsmål kollegaen faktisk vil bruke i arbeidshverdagen.

3. Juster språk og output

Hvis svarene blir for tekniske, strammer vi presentasjon og prompts.

4. Vurder delt løsning

Delt nettversjon kommer først når innlogging, logging og lesetilgang er avklart.

10 · Hva er allerede kontrollert?

Den lokale versjonen er testet før overlevering

Teknisk verifisering

  • Serveren kan lastes og viser forventede funksjoner.
  • Tester bekrefter at tomme søk og farlige filstier avvises.
  • Dokumentinnhold begrenses, så modellen ikke får store rådump ved et uhell.
  • Repoets test, lint og build passerer.

Bruksverifisering gjenstår

  • Test med ekte kollegaspørsmål.
  • Sjekk at svarene er forståelige for ikke-tekniske lesere.
  • Se om kildestatus er tydelig nok.
  • Bestem om Claude Desktop-pakke eller hosted versjon er neste behov.
