## 1. Operating rules for Codex (non-negotiable)

These encode `CLAUDE.md`, `.claude/source-attribution-policy.md`, and `.claude/research-workflows.md`. Read those files at session start; the summary here does not replace them.

1. **Source discipline.** Every imported claim/actor/number carries a primary locator (URL/DOI/local file). Registry data (Brønnøysund, Økoguiden API) → `machine_verified`. Self-reported/org-page data → `unverified` + flagged for human review. Never promote to citable without an independent primary source. Mirror sources (e.g. Comtrade) never become primary when a national source exists.
2. **Fail-closed honesty.** Empty cells stay empty. "Capacity" is not "realized volume". "Utilized" is not "high-value". Parked claims are verified or downgraded, never silently reused. Type-C gaps (no source exists) are findings, not failures.
3. **Repo conventions.** Outputs go to the paths specified per mission (mostly `research/external/r13/`, `research/_status/`, `research/forstaelse/`). Follow existing file-naming patterns (`<tema>-<beskrivelse>-YYYY-MM-DD.md/csv`). Reception logs (`mottakslogg`), uncertainty logs (`usikkerhetslogg`), and review queues (`review-koe`) accompany every actor-import batch — copy the pattern from the 2026-06-25/26/27 runs in `research/_status/`.
4. **Gates.** Each backlog row names its gate: `PCQ` (primary-claim qualification — number must have a primary source and method label before it may enter the DB/whitepaper), `actor-gate` (actor stub allowed as unverified, promotion requires primary locator), `source-shortlist` (deliverable is a vetted source list + memo, not DB rows), `forstaelse` (understanding memo only). Respect the gate; do not upgrade a deliverable class.
5. **Verification before completion.** Per session that touches the DB or committed artifacts: `npm run db:audit`, `npm run audit:citable` (if claims touched), `npm run audit:domain-coverage` (if actors touched), `npm run audit:research-artifacts -- --base=origin/main` (always for research files), `npm run test && npm run lint && npm run build` (if code touched). No PDFs >50MB into git.
6. **Session budgeting.** Prior runs stopped on token budget with margin reserved for report + verification + PR (see `research/_status/domene-sluttrapport-2026-06-25.md`). Plan each session: pick ONE batch below, reserve ~20% budget for logs, coverage regeneration, and the closing report. Cell floor: `min(20, estimated_universe)` nodes per cell per run; two dry gather-rounds documented = cell may be marked saturated for the run.
7. **Surgical scope.** No adjacent refactors, no speculative schema changes, no new documentation beyond the specified artifacts.
